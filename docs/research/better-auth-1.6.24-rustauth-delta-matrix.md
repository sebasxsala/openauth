## Disposition vocabulary

- `already equivalent` — current evidence establishes the same observable result or a strictly stronger contract that does not create an incompatible public claim.
- `missing` — current evidence establishes an observable gap.
- `historically divergent` — RustAuth already chose or documented a different observable contract before this target.
- `newly in scope` — the v1.6.24 behavior is mapped, but the v1.6.9 baseline has no target-specific proof; its owner ticket must select and prove the exact contract.
- `excluded` — the behavior is outside the declared Rust server/runtime surface after shared server implications are mapped elsewhere.

`newly in scope` is deliberately not treated as proof of a defect. Security-sensitive owner tickets must determine privately whether RustAuth is already stricter before publishing implementation detail.
